## 新版（待评测数字回填后使用）

> ### 本地 LLM 代码执行沙箱引擎（Python / Pandas / OpenAI 兼容 API）　2026.06 – 2026.09
> - **受控执行**：LLM 生成的 pandas 代码经 AST 白名单校验后在独立子进程执行，超时 + 内存
>   看门狗按进程树兜底，结果只以 JSON 回传不反序列化；发现并修复 Windows venv 启动器壳
>   导致"看门狗量错进程、击杀留孤儿"的缺陷。
> - **评测驱动**：自建 18 题六类评测集（含比率列求和口径陷阱），黄金答案运行时现算；
>   glm-4-flash 上一轮成功率 83.3%，口径陷阱题 3/3 全过，P50 延迟 16.4s，全程零超时
>   零拦截；3 道失败均为问句理解问题而非代码执行失败。
> - **数据不出域**：脱敏模式只外发列名与聚合统计；导出侧转义公式注入（OWASP CSV
>   Injection）；密钥仅存本机 .env。
> - **引擎/界面分离**：同一引擎支持 Streamlit 与 `python -m analyzer` CLI 双入口；
>   移除 LangChain 全家桶，直接依赖 15→12。

## 使用注意

1. 数字以 `analyzer/evals/results/eval_report.md` 为准（2026-09-13，glm-4-flash：
   一轮 15/18=83.3%，P50 16.4s，口径陷阱 3/3）。面试被问"怎么测的"，答评测口径
   四件套（一轮率/最终率/收敛分布/P50·P95）。
2. 3 道失败题是比满分更有价值的谈资：两道复合双问句只答一半、一道"单日最高"
   被算成单笔——这说明失败集中在**问句理解**而非执行层，给出下一轮迭代方向
   （问句分解/澄清追问）。能讲清"失败长什么样"比声称 100% 更可信。
2. "发现并修复启动器壳缺陷"是本次重构最值钱的一句话——它把"我用了 AI"翻转成
   "我审查了 AI"，面试时主动讲这条链路：测试失败 → 观测 RSS 恒 5MB → 假设启动器壳 →
   psutil 验证进程树 → 按树监控击杀。
3. 若被问"为什么做网页版"，答分层叙事：引擎是资产，网页只是演示壳，CLI 才是无界面
   真实工作流——2026 年做这个项目的价值在引擎不在壳。
