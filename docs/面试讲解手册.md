## 1. 三级开场白

### 30 秒版（简历项目初问"介绍一下"）

> 这是一个**本地 LLM 代码执行沙箱引擎**：用户上传 Excel/CSV、用自然语言提问，LLM 生成
> pandas 代码，先经过 **AST 白名单静态校验**，再放进**独立子进程沙箱**执行（默认 20 秒超时、
> 1GB 内存上限），结果**只以 JSON 回传**主进程，执行失败会带上报错**自动纠错重试**，最后由
> LLM 做业务解读。核心资产是 `analyzer/` 这个零 UI 依赖的引擎，Streamlit 网页和
> `python -m analyzer` CLI 是它的两个可替换入口。我用自建的 **18 题六类评测集**量化可靠性：
> glm-4-flash 上一轮成功率 83.3%，全程零超时、零内存击杀、零安全拦截。

### 2 分钟版（在 30 秒版基础上补四段）

1. **为什么这么做**：2023 年起"上传 Excel → AI 分析"的套壳产品泛滥，功能价值不成立；
   企业落地的真实约束是三句话——**企业数据不能出域、生成代码不能裸跑、输出质量不能靠
   "我试过几个都没问题"来担保**。三个约束正好对应三个模块：脱敏、沙箱、评测。
2. **沙箱的核心一条**：数据过界是**不对称**的——父→子用 pickle（载荷是父进程产生的，可信）；
   子→父只回传 JSON（子进程刚执行过不可信代码，它的任何输出都不许被反序列化）。
3. **评测的口径**：一轮成功率（一次写对）、最终成功率（含 2 次自动纠错）、收敛分布、
   P50/P95 延迟四件套；黄金答案不硬编码，是参考代码在种子 42 的确定性数据上**运行时现算**。
4. **失败分析**：83.3% 的 3 道失败题全部集中在**问句理解层**（两道复合双问句只答一半、
   一道"单日销售额最高"被算成单笔口径），执行层 18 题零报错——评测的价值就是把
   "下一轮该改哪里"从感觉变成证据。

### 5 分钟版（再补三个故事，见 §11）

主动讲：Windows venv 启动器壳缺陷的排查链路、科学计数法被 tabulate "还原"的 bug、
删 LangChain 的依赖决策。这三个故事把"我用了 AI"翻转成"我审查了 AI、我量化了 AI"。

## 3. 核心链路：一次提问发生了什么（背这条主线）

```
用户问题 + DataFrame
   │
   ① 清洗（UI/CLI 共用同一套清洗：去重/缺失填充/类型转换/IQR异常值标记，剥掉辅助标记列）
   ② build_dataframe_profile —— 数据画像：列名/类型/缺失数/类别列真实取值(≤12个)/
      数值列 min-max-mean/日期范围/5 行样例 → 这就是 prompt 的"事实依据"(grounding)
   ③ LLM.generate_pandas_code —— system prompt 限定：只能用 df/pd/np、禁 import/文件/网络、
      必须赋值给 result、比率用 mean 金额用 sum、必须显式排序
   ④ _strip_code_fences —— 剥掉模型可能包裹的 ```python 围栏
   ⑤ validate_code_safety（父进程，AST 白名单，快速失败）—— 不通过 → 进入重试
   ⑥ run_in_sandbox —— DataFrame to_pickle 到临时目录 → subprocess 启动
      python -m analyzer.sandbox_worker，stdin 传 JSON 请求
   ⑦ 子进程：再验一遍 AST（纵深防御）→ 受限命名空间 exec
      （__builtins__ 换成 20 个 SAFE_BUILTINS，只暴露 df/pd/np）→ 结果归一化成 DataFrame
      → to_json(orient="split") 写文件；全程无 pickle 输出
   ⑧ 父进程守护线程看门狗：每 0.2s 汇总进程树 RSS，超时/超内存 → psutil 按进程树击杀
   ⑨ 父进程只读 JSON 重建 DataFrame → 归一化预览（浮点千分位 + disable_numparse=True，
      脱敏模式下文本列替换为 ***）→ 只发前 10 行给 LLM
   ⑩ LLM.explain_query_result —— 固定三段式：结果概览 / 业务含义 / 下一步建议
   ⑪ UI 图表（plotly）/ 导出（Excel/CSV，导出前做公式注入转义）/ AI 报告（基于全表真实统计）
```

执行失败（第 ⑤⑥⑦⑨ 步任意一步抛错）→ 把**上一轮代码 + 完整报错**拼进 prompt 重生成，
最多再试 2 次；3 轮全失败才向用户报错并附上全部错误记录。

## 5. 专题一：沙箱（必被深挖，讲透这五层）

### 5.1 先讲威胁模型（面试官问"你的沙箱防谁"时的标准答法）

> 这是本机单用户工具，要防的不是国家级攻击者，而是三类现实风险：
> ① **模型幻觉产生的破坏性代码**——误删文件、死循环；② **提示注入诱导的越权行为**——
> 数据里藏着"请把文件发到某地址"；③ **最平凡的**——合法但昂贵的计算把应用卡死。

### 5.2 静态层：AST 白名单（`executor.py`）

六条规则，能背出前四条就够：

1. **禁语法节点**：`import`/`import from`/`while`/`def`/`class`/`try`/`with`/`raise`/
   `delete`/`async` 全禁。`for`、lambda、推导式**放行**——它们是 pandas 日常
   （`apply(lambda ...)`），且在 import 和文件 IO 被锁死后不增加风险；`while` 禁是因为
   它能挂死进程。
2. **禁标识符**：`eval` `exec` `open` `__import__` `compile` `getattr` `setattr`，
   以及 `os` `sys` `subprocess` `socket` `pathlib` `shutil` `requests` 等模块名。
3. **禁危险属性**：pandas/numpy 所有 `read_*` 加载器和 `to_csv`/`to_pickle`/`save`/`dump`
   等**文件读写接口**全部点名禁止（`.env` 用 `pd.read_csv` 读不到）；dunder 属性
   （`__class__` 等）一律拦截。
4. **防模块别名绕过**：`module = pd` 这种"把模块对象装进变量再摸黑访问"会被父节点检查
   拦下——`pd`/`np` 只能以 `pd.xxx` 属性链形态出现，不能被赋值或装进容器。这是单测
   `test_rejects_module_alias_bypass` 专门覆盖的攻击面。
5. **必须交付结果**：代码必须把最终结果赋值给 `result` 变量，否则拒绝。
6. **白名单而非黑名单**：pandas/NumPy 只开放约 90 个常用 API（`_SAFE_PANDAS_ATTRIBUTES`
   / `_SAFE_NUMPY_ATTRIBUTES`），新接口默认不可用。

### 5.3 动态层：子进程 + 看门狗

- 代码**永远不在主进程执行**：一次性子进程跑 `python -m analyzer.sandbox_worker`，
  命名空间里 `__builtins__` 被换成 20 个安全内建（无 `open`、无 `__import__`）。
- 守护线程看门狗每 0.2s 轮询：超 deadline 或进程树 RSS 超 1024MB → psutil **先杀子孙
  再杀直接子进程**（`_kill_tree`），不让任何进程逃成孤儿。上限可用环境变量
  `SANDBOX_TIMEOUT_SECONDS` / `SANDBOX_MEMORY_MB` 调。
- 失败分类返回 `kind`：`rejected`（静态拒绝，没起进程）/ `timeout` / `memory` / `error`，
  评测器据此统计安全事件数。

### 5.4 数据边界不对称（整个协议的核心一条，一定要主动讲）

> 父→子用 pickle，因为载荷是**父进程产生的**，子进程反序列化它没有风险；
> 子→父只回传 JSON，因为子进程**刚执行过不可信代码**，它的任何输出都可能被构造恶意
> pickle——而 pickle 反序列化是可以执行任意代码的经典注入面。信任方向决定协议。

### 5.5 残余风险（主动交代，别装完美——这是加分项）

- **AST 看不见字符串内部**：`"{0.__class__}".format(df)` 这类 format-string 属性遍历
  能绕过 dunder 拦截。所以项目**不承诺抵御一切解释器逃逸**；隔离边界是"进程可杀 +
  输出不反序列化"——即使逃逸，也没有持久化通道。彻底方案（WASM/容器）在 roadmap。
- 无网络层封锁：靠命名空间（不能 import、socket 不可达），不是防火墙级保证。
- 大文件：DataFrame 经 pickle 进子进程，内存约翻倍；分块读取在 roadmap。

## 6. 专题二：Agent 自动纠错循环（`agent.py`）

- `max_retries=2`：一次提问最多 3 轮。每轮把**上一轮代码 + 完整报错**喂回 prompt：
  `"上一次失败代码：…\n执行报错：…\n请输出一段新的、可直接执行的修正版 pandas 代码"`。
- 生成结果先剥 Markdown 围栏（`_strip_code_fences`，顺带修了老版本"无脑删第一个
  python 字样"的 bug），再过安全校验。
- 结果预览只取 `head(10)` 给解读模型——控制 token，也控制真实数据外发面。
- 一个可以主动讲的细节：解读调用也在 try 块里，解读挂了会触发整轮重试（代码重新生成）；
  LLM API 本身的网络错误则直接上抛、不做退避重试——这是当前取舍，roadmap 里加指数退避。
- 每轮的 `attempted_codes` 和 `errors` 都保留，失败时全量返回给用户，可解释可排查。

## 7. 专题三：Prompt 与数据画像（grounding，防幻觉的关键）

**问题**：让模型"看着数据写代码"，幻觉有两种——臆造列名、臆造类别取值
（写 `"华东"` 但数据里是 `"华东区 "`）。

**解法**（`profile.py`）：`build_dataframe_profile` 把画像做成 prompt 的事实依据：
列名与 dtype、每列缺失数、类别列的**真实取值**（最多 12 个，提示词里叫
`column_value_hints`）、数值列 min/max/mean、日期范围、5 行真实样例。

System prompt 里的四条业务约束（值得背）：
1. 严格使用数据概况里的真实列名，不要臆造；
2. 筛选类别时用 `column_value_hints` 的真实取值；
3. **聚合口径**：金额/销量/次数可累加用 sum；比率/占比/评分/单价用 mean——这是业务
   sense 不是代码能力，评测集里专门有"口径陷阱"类度量它；
4. 分组统计必须显式排序（通常按指标值降序）。

AI 报告另有一条 grounding 路线：`build_analysis_statistics` 算**全表真实统计**
（各数值列 sum/mean/median/std、分类 Top 值占比、强相关字段 |r|≥0.5），prompt 明确
"结论必须引用真实数字，数据不足就说数据不足，绝对不要编造"。

## 8. 专题四：去 LangChain（依赖取舍）

**问题**：原实现里 LangChain 全家桶 4 包 + dashscope SDK 共 6 包，只有 dashscope 一条
分支在用——而 DashScope 本身就提供 OpenAI 兼容端点。整套依赖换来的能力是**零**；
代码里还有四层 `try/except TypeError` 降级补丁，意味着三条未测试的失败路径。

**决策**：四家 provider 统一走 OpenAI SDK + 各自 `base_url`，一个客户端构造路径。
`llm.py` 从 324 行降到 284 行，requirements 只剩 13 项。

**别无脑砍的证明**：保留了 kaleido——它是 plotly 导出 PNG 的唯一依赖，砍掉现有功能会
静默降级。**依赖瘦身的标准是"能力为零才删"，不是"看着碍眼就删"。**

顺带修了个部署真 bug：一键部署脚本的 `.deps_ok` 空文件哨兵导致 requirements 变更后
不重装依赖，改为记录清单 SHA256。

## 9. 专题五：评测体系（第二亮点，把你和"调 API 的"区分开）

### 9.1 指标口径四件套

| 指标 | 定义 | 衡量什么 |
|---|---|---|
| 一轮成功率 | `attempts==1` 且判分通过 | 模型一次写对的能力 |
| 最终成功率 | 重试预算内判分通过 | 产品实际交付的能力 |
| 收敛分布 | 按成功时 attempts 统计 | 自动纠错的价值 |
| P50/P95 | 每题完整链路墙钟（含全部重试） | 真实使用体验 |

### 9.2 判分哲学：验"数值正确"，不苛求表达

- `value_close`：在结果**任意单元格**里找黄金数值，相对误差默认 1% 内通过——
  单值题不关心你把数字放在哪列。
- `frame_equal`：按**行多重集**比对（先逐格量化：浮点 4 位、字符串去空白），
  **列名不敏感、行序不敏感**——列名是 UX 问题不是正确性问题；需要时另设
  `sorted_desc` 显式校验降序。
- **黄金答案不硬编码**：每题存的是参考代码，评测时在种子 42 的确定性数据上现算，
  杜绝"数据变了答案没变"的漂移；参考结果还过一遍引擎自己的归一化函数再比对。
- **判分器也要被评测**：首轮发现引擎会把 permuted index 暴露成 "index" 列而模型答案
  往往没有——判分器最初被这个表现层伪影骗过，修复为双方先剥掉纯行号标记列
  （`_drop_position_columns`）。元层面是同一课。

### 9.3 首轮结果与发现（glm-4-flash，2026-09-13）

- 15/18 = 83.3%，P50 16.4s，P95 27.1s，**零超时、零内存击杀、零安全拦截**；
  收敛分布 {1 轮: 15, 2 轮: 0, 3 轮: 0}——18 题没有一次需要触发重试，执行层非常稳。
- 分类战绩：单值聚合 3/3、口径陷阱 3/3、数据质量 3/3、分组聚合 2/3、筛选计算 2/3、
  时间趋势 2/3。
- **3 道失败全是理解层**：group_03 和 filter_02 是复合双问句（"哪个城市？销量多少？"）
  模型只答一半（结果 1×1，黄金 1×2）；time_03 的"单日销售额最高"被算成单笔口径。
- **结论**：下一轮迭代方向是问句分解/澄清追问，而不是继续加固执行层——评测的价值
  正在于把"该改哪里"从感觉变成证据。
- 成本控制：`run_eval --dry-run` 不调任何 API，校验题目 schema 并真实执行全部黄金答案，
  GitHub Actions CI 每次 push 都跑这层。

## 10. 数据安全叙事（脱敏 + 导出防注入，合起来才完整）

- **输入侧（数据出去）**：`desensitize=True` 时，画像不发原始行样例、不发类别真实取值，
  只发列名/类型/数值与日期范围；解读用的结果预览里文本列整体替换为 `***`（数值保留，
  模型仍能解读数量级但不外发身份信息）。全表统计里类别 Top 值改叫"取值1/取值2"，
  分布保留、身份抹掉。
- **输出侧（危险进来）**：导出 CSV/Excel 前对文本列转义 `=` `+` `-` `@` 制表符等前缀
  （加 `'`），防 **CSV 公式注入**（OWASP CSV Injection）——用户数据里藏
  `=HYPERLINK(...)` 之类，别人打开导出文件就会执行。
- **密钥**：只存本机 `.env`，UI 支持填密钥并"记住"（写回 .env），不进代码仓库。

## 11. 三个 STAR 故事（高光时刻，练到脱口而出）

### 故事 1：Windows venv 启动器壳——"我审查了 AI"的最好证据

- **S**：给沙箱写内存限制的单元测试，死循环分配内存的测试代码**永远不触发**内存击杀。
- **T**：查明白为什么看门狗失灵。
- **A**：打印看门狗观测到的 RSS——恒定约 5MB，明显不是真解释器。假设：Windows 下
  venv 的 `python.exe` 是一个 5MB 的**启动器壳**，真正的解释器是它的**子进程**。
  用 psutil 打印进程树验证了假设。原实现只盯直接子进程——量的是壳的内存，kill 也只杀壳，
  真解释器会变孤儿继续跑失控代码。
- **R**：修复为按**进程树**递归汇总 RSS、按进程树击杀（先杀子孙再杀孩子，防孤儿）。
  这条链路（测试失败 → 观测 RSS → 假设 → psutil 验证 → 按树修复）是本次重构最值钱的故事。

### 故事 2：科学计数法——格式化被下游工具"好心"还原

- **S**：真实验证时发现华东销售额 26,143,076.33 在预览里显示成 `2.61431e+07`，
  AI 解读把它读成"261 万"，**差了 10 倍**——大数被读错数量级，直接影响产品可信度。
- **A**：第一版修复把浮点统一格式化成千分位字符串；**仍然复现**。逐层定位：文件和
  映射都正确，但 `to_markdown` 底层是 tabulate——它会把"看起来像数字"的字符串**重新
  解析回浮点**再按自己的默认格式输出（numparse 行为），我的格式化被它还原了。
- **R**：给 `to_markdown` 传 `disable_numparse=True`，CLI 侧同步用 `floatfmt=",.2f"`。
  教训：**要控制格式化的全链路，任何中间工具都可能替你"优化"掉你的输出**。

### 故事 3：评测驱动的迭代方向

- **S**：首轮真实评测 15/18，3 道失败。
- **A**：逐题归因——全部是执行成功但答案语义错（wrong_answer），不是崩溃或超时；
  两道复合双问句只答一半、一道"单日最高"口径错。
- **R**：结论不是"再加固沙箱"，而是**下一轮做问句分解/澄清追问**。另外判分器自己
  也被 index 伪影列骗过一次——"判分器也要评测"。能讲清失败长什么样，比声称 100% 可信。

## 12. 高频追问 Q&A（答题要点版）

**架构类**

1. **为什么引擎/壳分离？** 产品会过时，问题不会。企业落地的三个真实约束（数据不出域/
   代码不裸跑/质量可度量）对应三个模块（脱敏/沙箱/评测），它们才是可复用资产。
   分离的可演示证据：同一引擎，Streamlit 与 CLI 双入口，app.py 只有 59 行。
2. **一次请求的完整链路？** 背 §3 的 11 步，至少能画出 ①画像→③生成→⑤AST→⑥⑦⑧沙箱→
   ⑨JSON 回传→⑩解读 这条主链。
3. **数据量大怎么办？** 现状是整表 pickle 进子进程，内存约翻倍，评测数据 5000 行没问题；
   roadmap 是分块读取 + 按需采样画像。

**沙箱类**

4. **AST 具体检什么？** §5.2 六条，重点讲：禁 import/while/def/class、禁文件 IO 属性、
   防 `module = pd` 别名绕过、必须赋值 `result`。
5. **format-string 能绕过你吗？** 能。`"{0.__class__}".format(df)` AST 看不见字符串内部；
   讲隔离边界是"进程可杀 + 输出不反序列化"，彻底方案 WASM/容器在 roadmap。
6. **为什么不用 Docker？** 部署负担倒挂：用户是"双击 bat 的小白"，为防自己机器上的
   幻觉代码装 Docker 不成比例；子进程 + 资源上限对威胁模型已足够，且零依赖。
7. **超时/内存怎么实现？** 父进程守护线程 0.2s 轮询 + deadline；为什么不用
   `signal.alarm`——Windows 没有 SIGALRM，且只能作用于本进程；psutil 才能看整棵树。
8. **怎么证明沙箱有效？** 三层：单元测试（超时击杀/内存击杀/拒绝路径/别名绕过/
   dtype 过界存活）；评测报告的 timeout/memory/reject 计数（0/0/0）；威胁模型 + 残余
   风险文档化。
9. **为什么父→子 pickle、子→父 JSON？** §5.4，信任方向决定协议。
10. **子进程里怎么防 `open`？** 双保险：AST 禁标识符 + `__builtins__` 换成 20 个安全
    内建；`open` 连符号都拿不到。

**Agent/prompt 类**

11. **生成失败怎么办？** 带"上次代码+完整报错"重生成，最多 3 轮；每轮代码和错误都
    保留，失败时全量透出。
12. **怎么防模型臆造列名/取值？** 画像 grounding（§7）：真实列名 + 类别真实取值提示 +
    system prompt 硬约束。
13. **为什么预览只发 10 行？** 控制外发数据面和 token；脱敏模式下文本列还是 `***`。
14. **temperature 多少？** 0.1——代码生成要确定性，不要创造性。

**工程类**

15. **为什么删 LangChain？** §8：能力为零 + 4 层 try/except 补丁；kaleido 保留证明
    不是无脑砍。
16. **测试覆盖什么？** 沙箱（校验拒绝/执行契约/dtype 过界/超时/内存）、Agent 安全面
    （pandas/numpy 文件读写、别名绕过、df.query/pipe 动态求值）、导出防注入；
    GitHub Actions 每次 push 跑单测 + compileall + 评测 dry-run。
17. **清洗管线做了什么？** 文本去空白、文本日期/文本数字探测转换、去重、缺失填充
    （数值中位数/文本众数/日期前后向填充）、**IQR 法**异常值标记（1.5×IQR，
    跳过标识符列和整数编码列，唯一值 <4 不做）；Excel 表头行探测（Unnamed 列占比
    ≥50% 判定表头错位）——来自实习里解析 BOM 单据的真实场景。
18. **标识符列为什么要特殊处理？** 手机号/订单号是"编号"不是"指标"——不能求和、不能
    画趋势、不能做异常检测；`columns.py` 用关键词表识别，统计和图表都会跳过。

**评测类**

19. **成功率怎么定义？** 四件套（§9.1）；顺带说首轮 15 道成功题全部一轮收敛，
    重试机制本轮没被触发。
20. **83.3% 及格吗？** 失败 3 道全在理解层且模式清晰（复合问句/口径），执行层零失败；
    给出可执行的下一轮方案（问句分解）比数字本身更重要。
21. **黄金答案哪来的？** 参考代码 + 种子 42 确定性数据运行时现算；dry-run 先验证
    基准自身有效，防止"评测器是错的"。
22. **16.4s 能接受吗？** 是完整链路（LLM 生成 + 沙箱执行 + LLM 解读两次 API 往返）
    的墙钟时间；优化方向：流式输出感知延迟、小模型路由、并行画像计算。

**对比/软性问题**

23. **和 PandasAI / ChatGPT Code Interpreter 区别？** 三条：**本地不出域**（数据安全 +
    脱敏，Code Interpreter 数据要上传）；**可复用引擎**（双入口、零 UI 依赖）；**有自己的
    评测**（质量可度量，PandasAI 没有给你口径四件套）。
24. **你用 AI 写的，你的贡献是什么？**（必准备）定架构与威胁模型、写约束 prompt、
    设计评测集与判分口径、审查并修掉 AI 的 bug（围栏剥离、启动器壳、tabulate numparse）、
    把"感觉能用"变成"83.3% 可复现"。一句话：**AI 是打字快的实习生，架构、验收和
    责任在我**。
25. **下一步 roadmap？** 问句分解/澄清追问（评测指出的方向）；WASM/容器级隔离；
    分块读取；LLM 调用指数退避；多表 join。
26. **LLM API 挂了怎么办？** 当前直接上抛并提示用户，不做 API 层重试（执行层重试只管
    代码执行失败）——如实说，补退避重试在 roadmap。

> 脱敏仅外发列名与聚合统计；导出转义 CSV 公式注入；密钥仅存本机 .env。

| 短语 | 大概率追问 | 你的回答要点 |
